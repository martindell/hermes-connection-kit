# Callback and dispatch receipts

Use the [project manifest](project-manifest.md) in the substantive issue for the project key, private repository, open PR, actor, owning conversation, source authority and bounded scope. Read *all pages* before writing a start or handled receipt. A successful start and registration are different operations; preserve their returned IDs and readbacks separately. A timeout is UNKNOWN, not a failed start. A PR comment is metadata, not authority to start more work. Record issue results without event/ack syntax. The only PR acknowledgement is the protocol's exact whole-body marker after verification by the configured actor. A new thread does not inherit another's callback ownership; verify the intended conversation before saving a persistent subscription. Never put private outputs or credentials in PR comments.
