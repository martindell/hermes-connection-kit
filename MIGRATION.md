# Stopped-only migration helper (offline-reviewed source)

`migration.py` is a generic, stdlib file transaction, not a service controller. It never disconnects, connects, reloads systemd, reads credential contents, registers jobs or posts events. Its host-specific JSON manifest is private and excluded from Git. It acquires the existing owner-only `operation.lock` inode (nonblocking exclusive flock) before stopped checks and holds it through backup, mutation and return; a concurrent lifecycle command or migration refuses rather than racing. Never remove or replace this lock. `dry-run` verifies old hashes, immutable pins, new sources, credential metadata, directory modes, the stopped tunnel, observer timer/tick and control service (service MainPID zero), and absence of listeners at both tunnel and control ports. If any is active, even dry-run refuses; that is not an invitation to stop it during preparation.

Under a separately approved disconnected window, first record manager/process state and compare the reviewed manifest; stop the old unit using the authorised old lifecycle command and prove zero MainPID and neither listener. Run `python3 -I migration.py apply --manifest /private/stage/migration-manifest.json --backup /private/NEW-BACKUP` with a nonexisting owner-only backup destination. The helper saves prior bytes and a manifest-SHA-bound `transaction.json` in the new 0700 backup (0600 members) before any destination mutation. A failure before the transaction record leaves old destinations untouched; after it, do not connect or retry apply: inspect the state and use the same backup with rollback. The operator separately validates rendered static units and YAML, reloads the user manager and connects only with distinct approval. A successful apply is not activation.

For reversal, stop the managed unit and observer units under separate authority, confirm zero PIDs and neither listener, then `python3 -I migration.py rollback --manifest /private/stage/migration-manifest.json --backup /private/NEW-BACKUP`. Rollback requires the exact same manifest bytes, complete verified backup, and every destination in its recorded old/new/absent state; preflight checks ALL paths before any restoration. It restores old bytes and modes, removes only manifest-listed new files, and retains backup, credentials and persistent state. An interrupted rollback can be repeated with the same backup. A foreign edit or missing journal refuses before writing anything; manual reconciliation is then required. The operator separately reloads the user manager and decides whether to reconnect; the helper never replays a job.

Manifests are JSON objects with exactly `unit`, `observer_units` (timer, tick service and control service), `listener_port`, `control_port`, `lock_path` (existing lifecycle lock), `credentials` (two owner-only regular file paths, metadata only), `immutable` (path and SHA-256 for retained binary/config), `directories` (path, old_mode or null, new_mode as integer), and `files` (destination path, old_sha256 or null, source path or null, new_sha256 or null). The host-specific stage must use 0600 files and a 0700 directory. This helper is deliberately not a general package installer or live cutover command. No CLI path contains credential contents. Tests use disposable fictional files and fake manager responses; they cannot qualify a real host migration.
